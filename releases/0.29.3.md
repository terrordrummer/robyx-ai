# Robyx 0.29.3

**Quiet system-monitor cleanup.** Robyx no longer sends routine timestamp,
disk, memory, or process telemetry to Telegram (or any other chat) through the
legacy six-hour `system-monitor` task.

The automatic boot migration inspects `data/queue.json` and removes only
`periodic` entries whose task name or agent file identifies the old system
monitor. It preserves:

- every unrelated reminder, one-shot, periodic, and continuous task;
- historical messages and files;
- ad-hoc/on-demand diagnostics, including a one-shot task with the same name.

Corrupt queue state is never replaced with an empty queue: the migration uses
the shared verified recovery boundary and fails closed if no valid live file or
snapshot exists. Re-running it is safe and does not rewrite an already-clean
queue.

Linux and Windows installers also stop recreating the obsolete
`data/system-monitor` directory, and the operator documentation no longer
recommends routine telemetry as a scheduled teammate.

## Update compatibility

`min_compatible: 0.0.0` keeps the universal bridge introduced in `0.29.2`.
Any historical Robyx installation with a functioning updater can select this
tag directly. After restart, Robyx walks every pending in-process migration in
order and applies the `0.29.2 → 0.29.3` queue cleanup automatically; no manual
command or shell migration is required.
