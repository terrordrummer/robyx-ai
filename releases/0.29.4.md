# Robyx 0.29.4

**Updater smoke-test hotfix.** Release `0.29.3` exposed a protocol conflict in
the hardened update transaction: the updater correctly wrote
`data/backups/active-update.json`, then launched `bot.py --smoke-test`; the
bootstrap saw that same marker and rejected the updater's own controlled child
as though it were an ordinary service boot.

The update then rolled code and data back safely, removed the marker, and kept
the previous release online, but it could never commit the target release.

This hotfix admits exactly one narrow lane through the marker guard:

- the process must be running with `--smoke-test`;
- the marker phase must be `smoke-test`;
- Git HEAD and `VERSION` must exactly match the marker's target commit/version;
- the dependency fingerprint must already match the parent transaction.

The smoke child never migrates personal runtime data and cannot launch a
fallback dependency installation. Normal boots, corrupt markers, stale
dependency fingerprints, and any phase/commit/version mismatch still fail
closed.

## Updating from 0.29.2

No manual recovery is needed when the failed `0.29.3` attempt completed its
verified rollback and `active-update.json` is absent. Check for updates again:
the universal `min_compatible: 0.0.0` bridge lets `0.29.2` select `v0.29.4`
directly. On restart, the version chain first applies the `0.29.3` cleanup that
retires the legacy periodic system monitor, then this no-op `0.29.4` step.
