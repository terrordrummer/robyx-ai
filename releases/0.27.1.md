# Robyx 0.27.1

Bugfix release for the Codex backend. Closes a field incident where every
Codex-backed workspace failed on the first turn with:

    AI Error: error: unexpected argument '-q' found
      tip: to pass '-q' as a value, use '-- -q'

    Usage: codex OPTIONS PROMPT
           codex OPTIONS <COMMAND> ARGS

No persisted state schema changes; the `v0_27_1` migration is a no-op.

## The incident

Codex CLI 0.124 (released after Robyx 0.27.0 was cut) removed three
top-level flags that `CodexBackend` had been emitting since the backend
was first wired in:

- `-q` / `--quiet` — non-interactive mode toggle.
- `--approval-policy <policy>` — autonomous-execution gate.
- `--system-prompt <text>` — explicit system prompt.

The replacement surface is the `exec` subcommand
(`codex exec --skip-git-repo-check -- <prompt>`). Approval policy is now
a TOML override (`-c approval_policy="never"`); `--sandbox
danger-full-access` is preserved verbatim. There is no `--system-prompt`
flag at all on `exec` — the prompt is the only positional argument.

Until 0.27.1, every workspace pinned to `backend="codex"` (and every
scheduled / continuous step routed through Codex) failed before the
model ever saw the user's message. The error surfaces in chat as the
literal `AI Error: ...` block above, so the symptom is unmistakable.

## What changed

### `CodexBackend.build_command` rewritten for 0.124+

`bot/ai_backend.py::CodexBackend.build_command` (and the spawn variant)
now emit:

    codex exec --skip-git-repo-check \
        -c approval_policy="never" \
        --sandbox danger-full-access \
        --model <model> \
        --cd <work_dir> \
        -- <prompt>

The `--` terminates option parsing so a prompt that happens to start
with a dash is not misread as a flag. `--skip-git-repo-check` lets
spawned runs work in directories that are not git repositories (the
default for many workspaces).

### System prompt inlined into the user message

`exec` has no equivalent of the removed `--system-prompt`. The
orchestrator's system instructions are now wrapped in tagged sections
inside the user message — the same pattern OpenCode has used since
0.22.x — with an explicit "follow these system instructions exactly"
preamble:

    Follow these system instructions exactly. They override any
    conflicting defaults.

    <system_instructions>
    ...
    </system_instructions>

    <user_message>
    ...
    </user_message>

### Approval policy via TOML override

`CODEX_APPROVAL_POLICY` (env) and the `approval_policy` constructor arg
still control the policy, but the wire form is now `-c
approval_policy="<value>"` instead of the removed `--approval-policy
<value>` flag. Default remains `never` — autonomous, unattended
execution — to match the existing Robyx contract for spawned agents.

## Tests

`tests/test_ai_backend.py` extended with regression coverage for the
new command shape:

- Exactly one `exec` subcommand at position 1.
- `-c approval_policy="never"` and `--sandbox danger-full-access`
  emitted by default.
- `--cd <work_dir>` and `--skip-git-repo-check` always present.
- `--` terminates options; the composed prompt is the only positional
  argument.
- System prompt inlined via the tagged-section template when present;
  bare message when absent.

Full backend suite (`tests/test_ai_backend.py`): **55 passed**.

## Upgrade notes

- Operators on 0.27.0 upgrade to 0.27.1 via the built-in auto-updater
  or `git pull` + `systemctl restart robyx`. The migration framework
  runs `v0_27_1.upgrade` as a no-op.
- Codex CLI 0.124+ is now required for any workspace pinned to
  `backend="codex"`. Older Codex CLIs that still expose the legacy
  `-q` flag will refuse `exec --skip-git-repo-check` and need to be
  upgraded (`npm i -g @openai/codex` or the equivalent installer for
  your platform).
- No action required for workspaces on `backend="claude"` or
  `backend="opencode"` — those backends are unchanged.
