# Robyx 0.28.3

**Rate-limit false-positive fix.** Working inside the robyx-ai workspace
(or any project whose codebase discusses rate-limit handling), agent
replies were being silently replaced with
`"Rate limit reached — retry in a few minutes."` even though the user's
Anthropic / Codex / OpenCode subscription was nowhere near its actual
usage limits. The root cause was a substring keyword scan running
against the assistant's free-form response text and against the
combined `stdout+stderr` of the CLI subprocess.

## What users will notice

1. **Replies that mention rate limits are no longer hijacked.** If an
   agent discusses rate-limit code, cites API documentation, or simply
   uses words like "throttling" or "limit reached" in a normal answer,
   you will now receive the actual response instead of the rate-limit
   placeholder.
2. **Real rate-limit errors still surface.** When the underlying CLI
   actually fails with a rate-limit message on stderr (non-zero exit
   code), the `STRINGS["rate_limited"]` message is still produced. The
   classification just no longer trusts stdout content.

## What changed

### Success path — `bot/ai_invoke.py`

Removed the substring scan against the assistant's parsed result text:

```python
# before:
if _is_rate_limited(text_lower):
    return STRINGS["rate_limited"]

# after:
# Do not infer rate limits from assistant content. Substring
# matches against free-form AI output produce frequent false
# positives; failure-path diagnostics are classified separately
# in _classify_error.
```

This is the change that resolves the user-visible symptom.

### Failure path — `bot/ai_invoke.py:_classify_error`

`_classify_error` now prefers stderr for keyword classification:

```python
def _classify_error(combined: str, err: str, out: str) -> str:
    # Prefer stderr for keyword classification. The non-streaming branch
    # builds ``combined = (stdout + " " + stderr).lower()`` — including
    # stdout means assistant content (which for some backends is just the
    # parsed text) leaks into the keyword test and produces false
    # positives (the most common one being "rate limit" matched against
    # an agent response that merely *discusses* rate limits). Fall back
    # to combined only when stderr is empty (some CLIs print errors to
    # stdout).
    haystack = (err if err else combined).lower()
    ...
```

This eliminates the same class of false positive on the non-streaming
branch (Codex, OpenCode), without losing detection when a CLI emits its
errors on stdout (fallback when stderr is empty).

### Defensive — `bot/ai_invoke.py:_is_rate_limited`

`_is_rate_limited` is now internally case-insensitive and its docstring
forbids calling it on free-form assistant output.

## Review

3-turn adversarial peer review with Codex CLI (`codex-cli 0.128.0`),
recorded at `research/claude-codex-rate-limit-review.md`. Both
reviewers signed off as `frozen` for the reported false-positive
symptom.

## Known follow-ups (deferred — out of scope for this patch)

Both reviewers agreed these are real but not blockers for the user's
reported symptom:

1. **`STREAM_RETRYABLE_KEYWORDS`** has the same anti-pattern: assistant
   content discussing networking errors (e.g. "connection reset by
   peer", "broken pipe") triggers silent retries up to `MAX_AI_RETRIES`
   with a fresh session. Major separate follow-up; needs the same fix
   shape (only retry on error-shaped payloads on success path;
   stderr-preferred on the non-streaming failure path).
2. **Structured rate-limit detection** via Claude Code stream-json
   `is_error` / `subtype` / `system/api_retry` events. Requires a
   captured real-world rate-limit sample to verify the exact event
   format before implementation — both reviewers explicitly refused to
   speculate on the format.
3. **Keyword categorisation** — distinguish rate-limit (retry-soon),
   quota/billing (longer-term), server-overload (transient server),
   network (transient client). Different recovery semantics; current
   logic collapses all to `STRINGS["rate_limited"]`.
4. **`_read_stream` event metadata** — surface `is_error`/`subtype`
   instead of collapsing error result events into
   `STRINGS["ai_empty"]`. Changes return contract; coordinate with #2.
