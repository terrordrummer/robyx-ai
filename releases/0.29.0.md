# Robyx 0.29.0

**Security, resilience, and release-engineering hardening.** This release is
the result of the RR-00–RR-11 repository-wide review. It closes every confirmed
P0/P1 finding from that program, reconciles the runtime contracts and operator
documentation, and adds reproducible quality gates across Python 3.10–3.14.

There are no breaking user workflows and no manual data migration. The
version-chain migration is intentionally a no-op: compatible loaders and
recovery boundaries own the new persisted fields.

## Highlights

### Collaborative execution fails closed

- Participant AI is disabled by default. Operators may explicitly enable a
  stateless read-only profile when the workspace contains no confidential
  readable data.
- Claude, Codex, and OpenCode receive typed, backend-specific participant
  policies; participant turns cannot reuse executive sessions or dispatch
  side-effect markers.
- Telegram, Discord, and Slack now share destination, role, command, voice,
  and lifecycle authorization boundaries. Foreign chats cannot fall through
  to the HQ orchestrator.

### Continuous tasks have durable identity and recovery

- Task ownership is persisted as canonical `(platform, chat, parent thread)`
  scope and checked by lifecycle and plan operations.
- `program.json` is revisioned authority for the task program, preventing a
  stale step-state write from erasing an accepted plan update.
- Stop, pause, complete, delete, workspace close, and same-name recreation are
  serialized with bounded process-tree drain and durable state ordering.
- Dedicated topics recover and repoint atomically; actionable failures have a
  bounded, exactly-once HQ fallback. Awaiting-input pins, state markers,
  orphan incidents, and delete-mid-drain journaling are wired end to end.

### Persistence and updates are recoverable

- Queue, continuous state, agent, collaboration, migration, and orphan-PID
  registries validate full semantic shapes. Corrupt data is quarantined,
  verified snapshots are tried newest-first, and unrecoverable stores refuse
  mutation instead of being overwritten with empty state.
- A central runtime supervisor retains background tasks, tracks exact child
  generations and process groups, and performs bounded TERM/KILL/reap during
  lifecycle operations and shutdown.
- The updater now resolves and verifies the exact advertised tag, snapshots a
  quiescent data tree, supervises all child processes, and completes rollback
  before normal work resumes. A durable maintenance marker makes interrupted
  updates recoverable at the next boot.
- Configuration changes use typed validation, atomic `.env` replacement, an
  isolated import preflight, and byte-for-byte rollback on failure.

### Installation and development are reproducible

- Setup and installers harden local permissions, stop the managed service
  before recreating its environment, and avoid exposing secrets through echo,
  ordinary environment inheritance, or recommended command-line flags.
- Runtime and development dependencies are hash-locked for every supported
  Python minor from 3.10 through 3.14. Bootstrap, updater, installers, and CI
  select the matching lock and fail closed on drift or missing tooling.
- CI enforces critical Ruff checks, gradual mypy boundaries, warnings policy,
  dependency-lock drift, full tests, and coverage floors on high-risk modules.

## Platform and media fixes

- Discord collaborative messages use canonical guild/channel identities and
  reconnect without duplicating boot, scheduler, updater, or delivery tasks.
- Slack voice downloads are streamed with a 25 MB cumulative cap, bounded
  allowlisted redirects, retry parity, and guaranteed partial-file cleanup.
- Telegram retries transient topic mutations; all adapters expose a common
  permanent-unreachable signal for safe recovery.
- Successful assistant prose that merely mentions transport or rate-limit
  diagnostics is delivered normally; retry classification inspects failed
  process diagnostics rather than free-form assistant content.

## Migration and compatibility

`bot/migrations/v0_29_0.py` advances the continuous migration chain from
0.28.3 to 0.29.0 without rewriting user data. Existing agent, collaboration,
queue, and continuous-task files remain load-compatible. New fields are added
through ordinary runtime writes after authoritative validation.

The participant read-only profile protects integrity, not confidentiality: a
read-capable backend can still see readable workspace files. Keep
`COLLAB_PARTICIPANT_POLICY=disabled` (the default) for sensitive workspaces.
