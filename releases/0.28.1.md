# Robyx 0.28.1

**`/clear` UX hotfix.** Three issues in the spec 007.1 chat-archive
command, surfaced by the owner immediately after the 0.28.0 rollout:

1. **Silent return for non-owner workspace/specialist calls.** The
   legacy `@owner_only` pattern returned without sending any reply when
   the caller wasn't the bot owner. The owner reported "no feedback" —
   this was the cause.
2. **Missed agent resolution in collab chats without forum topics.**
   `cmd_clear` only resolved the target agent via
   `manager.get_by_thread(msg.thread_id)`. In Telegram non-supergroups
   (or Discord guilds without forum topics) `thread_id` is `None`, so
   the lookup missed and the command replied with `clear_usage` instead
   of operating on the collab's bound agent.
3. **Loose HQ guard.** `platform.is_main_thread(chat_id, thread_id)`
   on Telegram returns `True` for ANY chat without a forum thread, not
   just HQ — a collab non-supergroup matched, falsely triggering the
   HQ refusal.

## What changed

- `bot/handlers.py:cmd_clear` rewritten:
  - Resolves the collab workspace via `CollabStore.get_by_chat_id`
    BEFORE the HQ guard so it can be used as an agent-name fallback.
  - HQ guard now requires `chat_id == CHAT_ID` AND no collab match
    AND `is_main_thread()` — eliminates the collab false-positive.
  - Target-agent resolution adds a third fallback: `manager.get(
    collab_ws.agent_name)` covers non-forum collab chats.
  - Defensive int/str variant lookup on `manager.get_by_thread` for
    cases where `state.json` persists `thread_id` as a string.
  - Non-owner refusal now sends an explicit `clear_not_owner` reply
    instead of returning silently.
- `bot/i18n.py`:
  - New `clear_not_owner` string ("`/clear` on `…` is reserved for
    the bot owner…").
  - Updated `clear_archived` / `clear_no_history` copy: 🧹 emoji
    headline + turn count for archived messages, e.g.:

    ```
    🧹 Conversation cleared.

    Session reset on `atlas`. The previous conversation (12 turns)
    was archived to `data/conversations/atlas/archive-20260513T184522Z.md`.
    The next message starts a fresh session.
    ```
- `bot/conversations.py:archive_and_clear` now returns
  `(archive_path, turn_count)` instead of just `archive_path`, so the
  handler can quantify the archive in its feedback.
- `bot/migrations/v0_28_1.py` — no-op migration to keep the chain
  continuous.

## Linux non-restart investigation

A separate issue the owner reported after the 0.28.0 rollout: the Linux
deployment did not restart automatically after auto-update. The Codex
code review found no static blocker in the 0.28.0 changes — the
migration is exception-safe, all imports parse, the lifecycle wiring
is sound. The likely root cause is at the operator/service layer:
either `systemd` swallowed a non-zero exit during startup, or the
auto-update flow's smoke test rolled back. Operator action item:
inspect `journalctl -u robyx-ai -n 200` and `bot.log` to confirm
which path fired. No code change ships in 0.28.1 for this — once we
have the logs we can either ship a 0.28.2 fix or close it as an
environment issue.

## Breaking changes

`conversations.archive_and_clear` return shape changed from `Path | None`
to `tuple[Path, int] | None`. External callers (none currently) must
adapt.
